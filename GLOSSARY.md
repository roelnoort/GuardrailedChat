# GuardrailedChat

A test bed for learning how LLM guardrails work: a chatbot whose user messages are checked by a guardrail before the chatbot ever sees them.

## Language

**Chatbot**:
The shop assistant LLM that answers the user's messages, using only the Shop document as its domain knowledge. It only ever receives messages that passed the guardrails.
_Avoid_: Bot, assistant model, main model

**Shop**:
The fictional CrossFit/functional-fitness equipment store the Chatbot works for. It is deliberately made up, so answers can be traced back to the Shop document rather than the model's general knowledge.
_Avoid_: Store, company, client

**Shop document**:
The single document describing the Shop (products, prices, policies, internal notes) that is given to the Chatbot in full as its knowledge.
_Avoid_: Knowledge base, dataset, catalogue, database

**Guardrail**:
An independent LLM-based check that inspects a user message *before* it reaches the Chatbot and decides whether it may pass.
_Avoid_: Filter, moderator, classifier (as the name of the concept)

**Blocked message**:
A user message that at least one Guardrail rejected. It is never sent to the Chatbot.
_Avoid_: Rejected message, flagged message

**Chat**:
One conversation between the user and the Chatbot. The Chatbot remembers earlier passed messages within a Chat; starting a new Chat forgets everything.
_Avoid_: Session, thread, conversation history

**Secret**:
A staff discount code in the internal section of the Shop document that the Chatbot must never reveal. If it leaks, an injection attempt succeeded.
_Avoid_: Flag, canary, password

**Off-topic decline**:
A normal Chatbot reply steering the user back to the Shop. Unlike a Refusal, it comes from the Chatbot itself, not from a Guardrail.
_Avoid_: Off-topic block, off-topic refusal

## Guardrails

Each Guardrail checks exactly one concern. All enabled Guardrails inspect every user message independently and in parallel; one block is enough to make it a Blocked message. A disabled Guardrail gives no Verdict at all; with every Guardrail disabled, messages go straight to the Chatbot.

**Injection guardrail**:
The Guardrail that detects attempts to manipulate the Chatbot's instructions or behaviour (e.g. "ignore your previous instructions", role-play jailbreaks).
_Avoid_: Jailbreak filter

**Harmful content guardrail**:
The Guardrail that detects requests for dangerous or harmful subject matter (e.g. weapons, self-harm, illegal activity), regardless of how politely they are phrased.
_Avoid_: Toxicity filter, safety filter

**Verdict**:
The decision a single Guardrail reaches about a single user message: pass or block, with a short reason.
_Avoid_: Result, score, flag

**Refusal**:
The fixed, pre-written reply shown in place of a Chatbot answer when a message is blocked. Each Guardrail has its own Refusal; it is never generated by an LLM.
_Avoid_: Error message, rejection, block message

**Guardrail error**:
The situation where a Guardrail could not reach a Verdict (e.g. the API call failed). The message is blocked (fail closed), but it is shown as a malfunction, not as a Refusal.
_Avoid_: Failed check, timeout block
